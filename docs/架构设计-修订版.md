# sme-decision-ontology — 架构设计（修订版）

> 本体驱动（统一领域模型）的中小企业**数据决策**套件，做"决策"而非"检索"。
> 本修订版应用 OpenClaw 审查结论 + 全网技术调研。

---

## 一、定位叙事（重写）

**一句话**：**数据与决策之间的薄层，agent 的可信决策 API。**

- 不是替代 ERP/OA/CRM 全模块，而是补它们**缺的决策层**（存储和流程它们做，决策本产品做）
- 不是"什么都要"的产品，是**一个锋利的东西**：把进销存台账变成可拍板的决策建议
- 决策是给人拍板的，**规则算、人拍板**；agent 可调（可信决策 API）

---

## 二、统一领域模型（"本体"降火）

**术语**：内部叫"统一领域模型"，对外叙事可叫"本体驱动"。SME 决策用不上 OWL/RDF/SPARQL，**实体关系图 + 实体消歧**才是真实价值。

**核心实体（多决策复用）**：
```
Product(产品) ──suppliedBy──> Supplier(供应商)
     │──hasInventory──> Inventory(库存)
     │──hasSales──> Sale(销售)
     │──producedBy──> Equipment(设备)
     │──hasCost──> Cost(成本)
Customer(客户) ──places──> Order(订单)
Order ──hasPayment──> Payment(回款/账龄)
```

**实体消歧（本体的实际价值，写进设计目标）**：
- 一物多码（同一产品不同 ERP 编码）
- 供应商重名/别名
- 多源数据同一实体的归并

**与 factory-ontology 复用**：产品/供应商/客户/订单/库存实体重叠高 → **schema 直接继承**（从 factory-ontology 的本体结构派生，不从零造）。

## 三、4 个决策模块组（收敛，砍 8 并 2）

| 模块组 | 决策 | 共享 | 依赖 |
|--------|------|------|------|
| **inventory** | D1 补货 / D2 缺货 / D3 呆滞 | 再订货水平 | 无 |
| **procurement** | D4 比价 / D5 供应商绩效 | 供应商评分 | 无 |
| **sales** | D6 销售预测 / D7 客户信用 | 销售+订单 | 无 |
| **equipment** | D8 设备维护 | 设备台账 | 无 |

**模块依赖图**（deployment.json 能表达）：
```
inventory → (无依赖, 独立可用)
procurement → (无依赖)
sales → (无依赖)
equipment → (无依赖)
```
4 组**互不耦合**，可单独部署。`{enabled:["inventory","sales"]}` 只装这两组。

**每个模块完整闭环**：数据接入 → 规则 → 可解释建议 → 行动建议 → 报告/API/预警。

---

## 四、数据接入层（一等公民，80% 的活）

**多源对接**（含从其他数据库对接）：
```
data_mapper/
  适配器: CSV / Excel / SQLite / MySQL / PostgreSQL / 手工录入
  → 统一 schema 映射 → 统一领域模型(实体消歧) → 决策规则
```

**关键设计**：
- 每源一个**适配器**（CSV 用 stdlib csv，Excel 用可选 openpyxl，DB 用可选 pymysql/psycopg2）
- **schema 映射层**：源列名 → 领域模型字段（映射表配置驱动）
- **清洗**：去重/空值/类型转换/单位统一
- **实体消歧**：多源同一实体归并

**分期**：一期 CSV/Excel/SQLite + 手工；二期 MySQL/PG（ERP 对接）。

## 五、确定性决策规则（零 token 零 ML）

纯 Python 函数（不引规则引擎框架——调研确认用框架是升维）。

| 决策 | 公式（技术依据） |
|------|-----------------|
| D1 补货 | `reorder = 日均出库×提前期 + 安全库存`（ERPNext 权威） |
| D2 缺货 | 当前库存 < 再订货水平 |
| D3 呆滞 | 周转率 < 阈值 |
| D4 比价 | 综合成本加权 |
| D5 供应商绩效 | 交期/质量/价格评分卡 |
| D6 预测 | 移动平均/指数平滑 |
| D7 信用 | 账龄/DSO |
| D8 维护 | 保修/服役/状态 |

**每个建议带依据**：当前值 / 阈值 / 公式 / 数据来源。

## 六、AI 原生（规则算，LLM 讲）

| 原则 | 落地 |
|------|------|
| **规则算** | 计算层零 token，确定性决策 |
| **LLM 讲** | LLM 只做翻译和解释（NL→结构化，或解释决策依据） |
| **NL 是辅助** | 主入口=结构化查询+模板；NL 结果**强制回显校验**（"你问的是 3 月还是 Q1？"） |
| **MCP server** | 暴露决策给任意 agent（ask/decision/export），可信决策 API |
| **模型层** | 本地 Ollama 优先，远端 DeepSeek 降级；`active` 切换；**未装 Ollama 时文档写清降级体验** |

---

## 七、决策到行动闭环（OpenClaw 点出的弃用主因）

建议之后**必须能落地**：
- 库存补货 → 生成**采购单草稿**（产品/数量/供应商）
- 缺货预警 → **预警推送**（钉钉/微信，本地日志）
- 信用风险 → **催收提醒**清单
- 设备维护 → **工单/维护提醒**

不落地就是报表，会弃用。第一版至少输出**行动清单**（可导出的待办/草稿）。

---

## 八、数据新鲜度（Excel 快照会过期）

- **数据日期标注**：每条数据记录来源日期
- **增量导入** / **定时同步**（可选 cron）
- 决策时提示"数据截至 X 日，已过期 N 天"——防工具悄悄变废

---

## 九、阈值与参数管理（决策工具的核心 UX）

- `config/thresholds.json`：安全库存/周转率/账龄/信用额度/保修期
- **谁设、怎么调、调了影响哪些决策**——文档说明 + CLI `threshold` 命令
- 按模块/按品类可配

---

## 十、Golden Test（确定性系统最可测）

- **基准集**：一套结构真实的中小企业合成数据
- 8 个决策公式**全部单元测试** + benchmark（各决策命中率）
- 继承 factory-ontology 口碑：确定性 + 可测试 + 可解释

## 十二、完整性分析（技术调研后）

| 维度 | 分析 |
|------|------|
| **技术可行性** | 8 决策=标准运营公式，纯 Python 确定性实现，已验证（ERPNext 补货公式） |
| **规则引擎** | 用纯函数不引框架（调研确认框架=升维），零依赖 |
| **数据接入** | 自建轻量 mapper（stdlib+可选库），不引 Airflow 等重型 ETL |
| **MCP** | 标准协议（5ire/harbor 生态），决策 API 可被 agent 消费 |
| **选择性部署** | 4 组互不耦合 + deployment.json 依赖表达 |
| **AI 原生** | 规则算+LLM 讲，NL 辅助+回显校验，本地优先 |
| **完整性** | 决策→行动闭环 + 数据新鲜度 + 阈值 UX + Golden test + factory 复用 |

**诚实边界**：决策域限"进销存+运维"运营闭环，**不含财务/人力/战略**；阈值需按行业调；数据合成示例需真实台账验证。

## 十三、落地路线

4. **多数据库对接**：MySQL/PG（ERP 对接，用户补充点）
