# sme-decision-ontology — 本体建模设计（中庸之道 · 鲁棒适应 · AI 原生）

> 目标：让中小企业**不用懂本体论**也能建出生产级跨表跨域本体。换行业只改 schema+数据，代码不动。
> 哲学：**中庸之道**——不过于复杂（不引 OWL 推理/SPARQL），不过于精简（不做玩具级平铺表），**足够用 + 鲁棒 + 强适应**。

---

## 〇、中庸之道的建模哲学

| 维度 | 过简(玩具) | **中庸(本设计)** | 过繁(OWL) |
|------|-----------|----------------|-----------|
| 模型 | 平铺 dict | **实体+属性+关系+约束+轻类层** | 类公理/推理 |
| 关系 | 无 | **N:1/1:1/1:N 跨表** | 复杂基数+传递 |
| 约束 | 无 | **required/unique/positive/基数** | 完整 OWL 约束 |
| 门槛 | — | **表格即实体/外键即关系** | 需本体专家 |
| 能力 | 玩具 | **跨域图谱+决策** | 完备推理 |

**"足够"** = 能表达 SME 进销存+运维全貌，能跨表跨域决策，不冗余；**鲁棒** = 脏数据/缺列/多源也能跑；**强适应** = 换行业/加模块不改代码。

---

## 一、设计目标

| 维度 | 目标 |
|------|------|
| **中庸** | 最小但完备的模型（实体/属性/关系/约束 + 轻类层） |
| **泛化** | 领域无关：阀门/食品/机械/化工通用 |
| **鲁棒** | 脏数据/缺列/多源不崩，缺省默认兜底 |
| **强适应** | 换行业/加表/新决策，schema 驱动不改代码 |
| **AI 原生** | LLM 辅助建模：从数据自动建议实体/关系/约束 |
| **多元化** | 多源数据 + 多领域共存 + 多模型切换 |

## 二、通用本体 schema（中庸：够用不冗余）

```jsonc
// config/ontology.json — 企业唯一本体定义（跨表跨域）
{
  "entities": [
    {
      "id": "Product", "label": "产品",
      "table": "products",              // 数据源表
      "key": "id",                      // 主键
      "attributes": [
        {"name": "name", "type": "string", "required": true, "label": "名称"},
        {"name": "cost", "type": "number", "label": "成本"},
        {"name": "category", "type": "string", "label": "类别"}
      ]
    },
    {
      "id": "Supplier", "label": "供应商", "table": "suppliers", "key": "id",
      "attributes": [{"name":"name","type":"string","required":true,"label":"名称"}]
    },
    { "id": "Inventory", "label": "库存", "table": "inventory", "key": "product_id",
      "attributes": [{"name":"stock","type":"number","label":"库存"},{"name":"safety_stock","type":"number","label":"安全库存"}] },
    { "id": "Sale", "label": "销售", "table": "sales", "key": "product_id",
      "attributes": [{"name":"date","type":"date","label":"日期"},{"name":"qty","type":"number","label":"数量"}] },
    { "id": "Customer", "label": "客户", "table": "customers", "key": "id",
      "attributes": [{"name":"name","type":"string","required":true,"label":"名称"}] },
    { "id": "Equipment", "label": "设备", "table": "equipment", "key": "id",
      "attributes": [{"name":"name","type":"string","label":"名称"},{"name":"status","type":"enum","label":"状态"}] }
  ],
  "relations": [
    {"id":"suppliedBy","from":"Product","to":"Supplier","label":"供应","cardinality":"N:1"},
    {"id":"hasInventory","from":"Product","to":"Inventory","label":"库存","cardinality":"1:1"},
    {"id":"hasSales","from":"Product","to":"Sale","label":"销售","cardinality":"1:N"},
    {"id":"producedBy","from":"Product","to":"Equipment","label":"生产","cardinality":"N:1"},
    {"id":"placedBy","from":"Order","to":"Customer","label":"下单","cardinality":"N:1"}
  ],
  "constraints": [
    {"type":"required", "on":"Product.supplier", "msg":"产品必须有供应商"},
    {"type":"positive", "on":"Inventory.stock", "msg":"库存不能为负"},
    {"type":"unique", "on":"Product.id", "msg":"产品编码唯一"}
  ]
}
```

**最小模型 = 实体(属性) + 关系(基数) + 约束**，所有企业知识都可用此描述。

## 三、跨表跨域（数据→统一图谱）

**外键推断（自动，简化）**：表头含 `*_id`/`*_code`/`*_name` 且指向另一实体主键 → 自动建关系。
- `inventory.product_id → products.id` → Product→Inventory
- `products.supplier → suppliers.id` → Product→Supplier

**手动声明（覆盖）**：schema 的 `relations` 显式声明跨域关系，支持多跳。

**本体实例图**：加载各表 + 按关系 join → 统一图（可跨域遍历）：
```
[供应商S01] --供应--> [产品P01] --库存--> [库存(50)]
                     [产品P01] --销售--> [销售记录×12]
                     [产品P01] --生产--> [设备E01]
```

## 四、简化策略（降低 SME 建模门槛）

1. **表格即实体**：一个 CSV 表默认一个实体，表头即属性，无需命名
2. **主键即标识**：`id`/`xxx_id` 自动识别
3. **外键即关系**：`*_id` 列自动推断关系（跨表）
4. **类型自动推断**：数值/日期/枚举/字符串 从数据猜
5. **schema 缺省**：不写 schema 也能跑（用默认约定），写了则精确控制
6. **label 缺省**：属性中文名默认用表头，可覆盖

## 四·五、AI 原生建模（LLM 辅助，降低建模难度）

**建模时**（`model_llm` 本地优先 + 云端降级）：
```
上传台账 CSV → LLM 分析表头/样本 →
  建议实体(每个表)、关系(外键推断)、约束(唯一/必填/基数)
  → 生成 config/ontology.json → 用户确认微调
```

**运行时**（强适应）：
- 新增表/列 → LLM 自动扩 schema + 建议新关系
- 数据异常（缺列/脏值）→ LLM 建议清洗规则
- 换行业 → LLM 按新表头重建 schema（领域无关）

**原则**：LLM 生成建议，**规则引擎兜底**（确定性校验），人拍板。AI 是建模助手，不是替代。

## 四·六、鲁棒性 + 强适应（企业一体化）

**鲁棒性（脏数据/缺列不崩）**：
- 缺失列 → 用默认值/跳过，不崩溃
- 脏值（空/类型错）→ 清洗 + 标注，不阻塞
- 多源（CSV/Excel/SQLite/MySQL/PG）→ 统一映射，某源失败不影响其他
- schema 缺省约定兜底 → 不写 schema 也能跑

**强适应（企业一体化，多领域共存）**：
- **多领域共库**：一个系统同时建模 阀门/食品/化工 多个子域（命名空间隔离）
- **多表多源**：同一实体可由多表/多源映射（如 产品 来自 ERP + 手工台账）
- **增量演化**：加表/加模块不重建，schema 增量更新
- **决策驱动**：新增决策类型只加规则函数，读同一本体图

## 五、生产级工程化

| 层 | 能力 |
|----|------|
| **schema 校验** | 启动时校验 ontology.json（实体/关系/约束合法性） |
| **约束执行** | required/positive/unique/cardinality 落地校验 |
| **实体消歧** | 一物多码、供应商重名归并（跨域质量） |
| **图谱查询** | 实体实例图 → 图遍历（从供应商查产品再查库存） |
| **数据新鲜度** | 数据日期标注 + 增量/定时同步 |
| **Golden test** | schema + 图 + 决策全链路单测 |

## 八、诚实边界

- 简化版不引入 OWL 推理/SPARQL（SME 用不上，避免升维）
- 关系基数/约束是"够用的最小集"（N:1/1:1/1:N + required/unique/positive），不做复杂本体公理
- "生产级"指**工程可靠**（校验/测试/可维护），非 OWL 语义完备
