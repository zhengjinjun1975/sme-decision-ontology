# sme-decision-ontology — 架构设计（完整工程）

> 本体驱动的中小企业**数据决策**套件（CSV→本体→确定性决策）。
> 定位：Odoo/ERPNext 太重、InvenTree 只存不决、金蝶用友上云之间的**真空**——本地、轻量、本体驱动、确定性决策。
> 思路：决策者视角——先定价值闭环，再落架构。

---

## 一、决策者视角的项目目标

| 维度 | 目标 |
|------|------|
| **价值** | 让中小企业把台账变成"能拍板的决策建议"（补货/缺货/定价/信用/维护），本地、零 token、可解释 |
| **差异化** | 一本体多决策（8 个决策共享实体关系），确定性规则，本地驱动 |
| **落地** | 纯 Python 零依赖核心，中小厂一台普通电脑可跑 |
| **AI 原生** | 自然语言问决策 + MCP server（任意 agent 可调），LLM 可选增强 |

---

## 二、本体建模（一次建模，多决策复用）

**核心实体（8 决策共享）**：
```
Product(产品) ──suppliedBy──> Supplier(供应商)
     │──hasInventory──> Inventory(库存)
     │──hasSales──> Sale(销售/订单)
     │──producedBy──> Equipment(设备)
     │──hasCost──> Cost(成本)   # 毛利/定价
Customer(客户) ──places──> Order(订单)
Order ──hasPayment──> (回款/账龄)   # 信用
```

**多表一本体**：每个决策的台账映射到本体实体——schema 一次，数据多源映射。

## 二·五、产品哲学（模块化 + 选择性部署 + 轻量定位）

**① 8 模块分离（插件式）**
每个决策是**独立模块**（数据源映射 + 规则 + API + 报告），通过**模块注册表**注册，互不耦合。

**② 选择性部署**
`config/deployment.json` 配置启用哪些模块，**不强制全装**：
```json
{ "enabled": ["inventory", "procurement", "credit"] }  # 只部署需要的
```
中小厂只需库存决策 → 只启 `inventory`，其余不装。

**③ 不轻易升维**
- 坚持**确定性规则**（零 token/零 ML），不引入重型框架
- 每个模块保持单文件级
- 只做"进销存+运维"决策，**不做**财务/人力/战略（避免膨胀）

**④ 用户易用易部署**
- `python run.py setup` 一键初始化 + `python run.py decision <模块>` 一键决策
- 纯 Python 零依赖核心，一台普通电脑可跑；Docker 一键
- 配置驱动（阈值/数据源/模型都在 config），用户改配置不改代码

**⑤ 功能完整**
每个模块完整闭环：数据接入 → 决策规则 → 可解释建议 → 报告/API → 预警推送

**⑥ 多源数据**
`data_mapper` 抽象数据源：CSV / Excel / SQLite / MySQL-PostgreSQL(ERP导出) / 手工录入，统一映射到本体

**⑦ 轻量替代 OA/ERP/CRM**
定位：不是替代 ERP 全模块，而是**轻量决策层**——替代常规进销存/OA/CRM 里的"报表 + 决策建议"部分（它们做存储和流程，本产品做**决策**）。中小厂用一套轻量系统管"补货/定价/信用/维护"决策。

## 三、8 个决策模块（确定性规则引擎，含技术依据）

| # | 决策 | 规则（标准公式，技术依据已验证） |
|---|------|------------------------|
| D1 | 库存补货 | **ERPNext 权威公式**：`reorder_level = (日均出库×提前期) + 安全库存`；EOQ |
| D2 | 缺货预警 | 当前库存 < 再订货水平 → 预警 |
| D3 | 呆滞识别 | 周转率 = 年出库/平均库存，低于阈值 → 呆滞 |
| D4 | 销售预测 | 移动平均 / 指数平滑（确定性，借鉴 Time-Series 模式） |
| D5 | 采购比价 | 综合成本加权（价格/运费/交期） |
| D6 | 供应商绩效 | 评分卡（交期准时率/质量合格率/价格）加权 |
| D7 | 客户信用 | 账龄分析(30/60/90天)、DSO（轻量，不用 ML） |
| D8 | 设备维护 | 保修/服役/状态 → 建议 |

**原则**：全部确定性（零 token、零幻觉、可解释）——每个建议带依据（当前值/阈值/公式）。

**开源借鉴**：InvenTree(7.3k)/ERPNext(37.7k) 的补货逻辑、供应商评分卡、移动平均预测——都是标准运营管理公式，纯 Python 可实现。

## 四、AI 原生设计

| 层 | 能力 |
|----|------|
| **自然语言问决策** | 复用 factory-ontology 的四级链路：规则引擎(确定性) → 逻辑桥(LLM转逻辑) → miss |
| **MCP server** | 暴露决策给任意 MCP-native agent（ask/trace/export 同款思路） |
| **LLM 可选** | 开放性问题用 LLM，结构化决策用规则（分工，不包打天下） |

## 五、模型层：本地优先 + 远端自由切换

复用 factory-ontology 的 `model_config.json` 模式：
```
config/model_config.json:
  "active": "local_ollama"   # 默认本地(优先本地)
  models:
    local_ollama:  { type: openai, base_url: http://localhost:11434/v1, model: qwen2.5:7b }  # 离线默认
    local:         { type: ollama, base_url: .../api/generate, model: ornith:latest }
    cloud:         { type: openai, base_url: api.deepseek.com, model: deepseek-chat }  # 远端备用
```
`model_llm.py`：支持 base_url 离线 + /v1 归一化；`active` 一键切换。**优先本地，云端降级**（本地不可用→远端）。

## 九、诚实边界

- 8 决策是"进销存+运维"运营闭环，**不含财务/人力/战略**（软性、无法确定性决策）
- 决策建议是**辅助**，最终拍板在经营者（"决策者"是给人，不是替代人）
- 规则是标准管理公式，**阈值需按行业/企业调整**（安全库存/周转率阈值可配）
- 数据为合成示例，真实落地需真实台账 + 阈值调优
